# Nightly Backups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every night, staging and production back up the app database, the Keycloak database and the MinIO photo store to the internal VM, encrypted. Old snapshots are pruned, a restore is tested every week, and an alert fires when either backups or the restore test stop working.

**Architecture:** The internal VM runs `restic/rest-server` in append-only mode with one private repository per environment, over TLS with a self-signed certificate that the clients pin. Each app VM runs a systemd timer: `restic backup` streams `pg_dump` output for both databases and backs up the MinIO directory, then writes a Prometheus textfile metric. The internal VM, which holds the repository passwords, runs forget/prune, `restic check` and a weekly restore into a throwaway Postgres container, and writes its own metrics. Prometheus alerts on both sets of metrics.

**Tech Stack:** Ansible (roles, community.general), systemd timers, restic 0.19.1, rest-server 0.14.0, Docker, Prometheus textfile collector and alert rules.

**Spec:** Owner decisions on 2026-10-14: back up to the internal VM now and add Backblaze B2 as a second copy later. Measured on 2026-10-14: `/srv/stack/backend` is 1.04 GB on production and 0.66 GB on staging, and the internal VM has 52 GB free.

## Global Constraints

- restic `0.19.1`, linux_amd64, sha256 `f415415624dcc452f2a02b8c33641791a8c6d6d3b65bbb3543fcf9a25151585c` (of the `.bz2`).
- rest-server image `restic/rest-server:0.14.0@sha256:d2aff06f47eb38637dff580c3e6bce4af98f386c396a25d32eb6727ec96214a5`.
- Postgres for the restore test: `postgres:17`, the same major the app VMs run.
- App VMs have no inbound change. The internal VM publishes 8000/tcp only to the app VMs, using the existing `docker_guarded_ports` DOCKER-USER guard.
- Retention: 7 daily, 4 weekly, 6 monthly.
- Secrets are generated by the vault bootstrap from `ansible/secrets-spec.yml`. No secret values in git, logs or metrics.
- Deploys go only through `.github/workflows/ansible-deploy.yml` on merge to `main`.

## Review Focus

1. If `pg_dump` fails partway (container down, disk full), the run must count as failed and must not write a "last success" timestamp. Test: the backup script with a stopped Postgres container exits non-zero and leaves the metric untouched.
2. A first run on a fresh repository must initialize it once, and a second run must not try again. Test: two consecutive local runs both succeed.
3. If an app VM is compromised, it must not be able to delete or rewrite old snapshots (append-only). Test: `restic forget` from the client against the local rest-server is refused.
4. The restore test must prove the data is usable, not just that files exist. Test: the restored dump loads into Postgres and a query on `"AuthUser"` returns a count.
5. If one environment's timer silently stops, the alert must fire for that environment even though the other keeps reporting. Test: in promtool, a series that stops updating for 26h fires `BackupMissing`.

### Task 2: Nightly backup on the app VMs

**Files:**
- Create: `ansible/roles/backup-client/tasks/main.yml`, `ansible/roles/backup-client/files/hero2-backup.sh`, `ansible/roles/backup-client/templates/hero2-backup.env.j2`, `ansible/roles/backup-client/files/hero2-backup.service`, `ansible/roles/backup-client/files/hero2-backup.timer`
- Modify: `ansible/playbooks/staging.yml` and `ansible/playbooks/production.yml` (add role `backup-client`). Add `backup_env: staging` to `group_vars/staging.yml` and `backup_env: production` to `group_vars/production.yml`.

**Interfaces:**
- Consumes: the repository URL and CA from Task 1. The CA is fetched from the internal VM with `slurp` (delegated) and written to `/etc/hero2-backup/rest-server.crt`.
- Produces: the metric `hero2_backup_last_success_timestamp_seconds{env}` and `hero2_backup_last_run_success{env}` in `/var/lib/node-exporter/hero2_backup.prom`.

- [ ] Step 1: Install restic. Use `get_url` for `https://github.com/restic/restic/releases/download/v0.19.1/restic_0.19.1_linux_amd64.bz2` with `checksum: sha256:f4154156...585c`, then `bunzip2` it to `/usr/local/bin/restic` with mode 0755, guarded by `creates`.
- [ ] Step 2: Write `hero2-backup.env.j2`, mode 0600, owned by root:
  `RESTIC_REPOSITORY=rest:https://{{ backup_env }}:{{ lookup('vars', 'RESTIC_REST_PASSWORD_' ~ backup_env | upper) }}@{{ groups.internal[0] }}:{{ backup_rest_port }}/{{ backup_env }}/`, `RESTIC_PASSWORD=...`, `RESTIC_CACERT=/etc/hero2-backup/rest-server.crt`, `BACKUP_ENV={{ backup_env }}`.
- [ ] Step 3: Write `hero2-backup.sh` with `set -euo pipefail`. Steps:
  - Run `restic cat config >/dev/null 2>&1 || restic init`.
  - Find each container with `docker ps -q --filter label=com.docker.compose.project=backend --filter label=com.docker.compose.service=<svc>`, for `<svc>` in `postgres` and `keycloak-db`. Exit 1 if a container is missing.
  - For each, run `restic backup --tag <svc> --stdin-filename <svc>.dump --stdin-from-command -- docker exec <id> sh -c 'pg_dump -U "$POSTGRES_USER" -Fc "$POSTGRES_DB"'`. restic fails the snapshot when the command exits non-zero.
  - Run `restic backup --tag minio /srv/stack/backend/volumes/minio`.
  - Only after all three succeed, write `hero2_backup_last_success_timestamp_seconds{env="$BACKUP_ENV"} $(date +%s)` and `hero2_backup_last_run_success{env=...} 1`, writing to a temp file and then `mv`, as `srv-disk-usage.sh` does.
  - On any failure, an `ERR` trap writes `last_run_success 0` and keeps the previous timestamp line, read back from the old file.
- [ ] Step 4: Write the service unit (`Type=oneshot`, `EnvironmentFile=/etc/hero2-backup/env`, `Nice=10`, `IOSchedulingClass=idle`) and the timer (`OnCalendar=*-*-* 03:15:00 UTC`, `RandomizedDelaySec=20m`, `Persistent=true`).
- [ ] Step 5: Local integration test, script at `scripts/test-backup-local.sh`. Start the Task 1 rest-server container and a compose project named `backend` with `postgres` and `keycloak-db` services (`postgres:17`, each seeded with one table and one row), plus a temp directory standing in for MinIO. Run `hero2-backup.sh` twice. Expect exit 0 both times, three snapshots per run, and the metric file holding a fresh timestamp. Stop the `postgres` container and run again. Expect a non-zero exit, `last_run_success 0`, and an unchanged timestamp.
- [ ] Step 6: Run `shellcheck` on the script, then `ansible-playbook --syntax-check` on both playbooks.
- [ ] Step 7: Commit `feat(backup): nightly encrypted backups from staging and production`.

### Task 3: Prune, check and restore test on the internal VM

**Files:**
- Create: `ansible/roles/backup-server/files/hero2-backup-maintain.sh`, `ansible/roles/backup-server/files/hero2-backup-maintain.service`, `ansible/roles/backup-server/files/hero2-backup-maintain.timer`, `ansible/roles/backup-server/templates/hero2-backup-maintain.env.j2`
- Modify: `ansible/roles/backup-server/tasks/main.yml` (install restic as in Task 2 Step 1, plus the files above)

**Interfaces:**
- Consumes: the repositories at `/srv/data/backups/<env>`, accessed through the local path, not over HTTP, so append-only does not apply.
- Produces: the metrics `hero2_backup_restore_test_success{env}`, `hero2_backup_restore_test_timestamp_seconds{env}` and `hero2_backup_snapshot_count{env}` in `/var/lib/node-exporter/hero2_backup_maintain.prom`.

- [ ] Step 1: Write the script. For each env in `staging` and `production`:
  - Run `restic -r /srv/data/backups/$env forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6 --prune`.
  - On Sundays, also run `restic check --read-data-subset=10%`.
  - Restore test, on Sundays or when no restore metric exists yet:
    - `restic dump latest --tag postgres postgres.dump > $tmp/app.dump`.
    - `docker run -d --rm --name hero2-restore-$env -e POSTGRES_PASSWORD=x postgres:17`, then wait for `pg_isready`.
    - `docker exec -i ... pg_restore -U postgres -d postgres --no-owner < app.dump`.
    - `docker exec ... psql -U postgres -tAc 'select count(*) from "AuthUser"'`. Pass when it returns an integer of at least 1.
    - Always `docker rm -f` the container and remove `$tmp`, through a trap.
  - Write the metrics atomically.
- [ ] Step 2: Write the timer (`OnCalendar=*-*-* 05:30:00 UTC`, `Persistent=true`) and the env file (mode 0600, holding both repository passwords).
- [ ] Step 3: Local test. Run the script against the repository the Task 2 test filled. Expect `restore_test_success 1`. Corrupt a pack file and expect `check` and the metric to report failure.
- [ ] Step 4: Commit `feat(backup): prune, check and a weekly restore test`.

### Task 4: Alerts

**Files:**
- Modify: `ansible/roles/monitoring-server/templates/alert-rules.yml.j2`
- Create: `ansible/roles/monitoring-server/files/alert-rules.test.yml`. If the repo has no promtool tests yet, run them in a container in Step 2.

- [ ] Step 1: Add the rules.
  - `BackupMissing`: `time() - hero2_backup_last_success_timestamp_seconds > 26*3600`, or `absent(hero2_backup_last_success_timestamp_seconds{env="production"})`, or the same `absent` for staging. `for: 30m`, severity critical. The description names the env and the `journalctl -u hero2-backup` command.
  - `BackupFailed`: `hero2_backup_last_run_success == 0`, `for: 5m`, severity warning.
  - `BackupRestoreTestFailing`: `hero2_backup_restore_test_success == 0`, or `time() - hero2_backup_restore_test_timestamp_seconds > 8*86400`. Severity critical.
- [ ] Step 2: Run `docker run --rm -v $PWD:/w prom/prometheus:v2.53.0 promtool test rules /w/alert-rules.test.yml` on the rendered rules. It covers a series that stops for 26h (fires), a fresh series (silent), and a missing production series (fires).
- [ ] Step 3: Commit `feat(backup): alert when backups or the restore test stop`.
